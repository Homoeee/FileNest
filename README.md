# FileNest

FileNest 帮你整理散落在不同文件夹里的资料：先查看文件，再选择规则、预览去向，确认后执行。它同时提供桌面窗口和网页版，两种入口使用同一套界面和本地数据，文件不会上传到外部服务。

## 能做什么

- **像文件管理器一样操作**：左右两栏浏览文件夹，查找、排序、打开文件，选中后移动、复制或重命名。
- **按规则批量整理**：按文件类型、名称、日期、大小等条件分类，可按年月归档，也能批量重命名。
- **执行前先核对**：预览每个项目的动作和目标位置；同名文件默认跳过，也可以自动编号，不会直接覆盖。
- **查记录并撤销**：查看每次操作的结果；符合条件的移动和重命名可以撤销。

例如，想把下载目录里积累的文档和图片分别归档：选择下载目录及目标目录，勾选需要处理的文件和分类规则，确认预览清单后再执行。未匹配规则的项目会留在原处；如果勾选文件夹，它的内部内容会按整体处理。

## 快速开始

如果拿到 Windows 便携包，解压整个 `FileNest-Windows-x64-*.zip`，双击 `FileNest.exe` 打开桌面窗口；偏好浏览器时双击同目录的 `FileNest-Web.cmd`。两种入口可以在页面右上角切换，切换时当前预览和历史仍由同一个本地服务保留。不要分别运行两个程序实例。

1. 在「文件管理」中浏览文件夹，或到「规则整理」填写来源目录和整理后的目标目录。
2. 在「规则管理」中检查或创建规则，勾选要处理的文件与规则，然后生成预览。
3. 核对来源、动作、目标位置和冲突提示，确认无误再执行；完成后到「历史与撤销」查看结果。

第一次使用建议先选少量样例文件，确认规则和目标目录符合预期后再扩大范围。执行中的任务可停止后续操作，已完成的部分会保留记录。

## 详细使用流程

1. 来源和目标均可手动输入完整路径，也可点击「选择目录」，在网页文件夹浏览器中逐层选择。多个来源用英文分号分隔。来源输入后按回车或移出输入框，自动加载文件列表；按需启用子目录。
2. 在规则管理中新增、编辑、删除或上移规则。按图片、视频、压缩包、文档、文件夹等类型筛选，可补充名称、扩展名、日期和文件大小条件。文件夹必须明确勾选；文件夹规则不使用文件大小条件。
3. 在「文件列表」勾选需要整理的文件，在「使用规则」展开所有现有规则，勾选一条或多条，也可全选或清空；按规则管理中的顺序采用第一条命中规则，可勾选按年月归档。点击「生成所选预览」，切换到「变更预览」核对动作与目标；可随时切回文件列表。未选文件不会进入计划。
4. 选择可执行项目，点击「立即开始整理」并确认。可以停止后续任务，已完成项会保留记录。
5. 在历史页面检查逐文件成功、失败和撤销结果。移动及重命名（含跨盘和文件夹）可在状态未变化、原位置无冲突时撤销。复制不自动撤销，回收站项目需在 Windows 回收站还原，永久删除无法撤销。

配置变更后必须重新生成预览。生成预览时自动保存当前配置，也可以点击「保存配置」或「保存偏好」。规则编辑弹窗保存后立即持久化；规则采用勾选、排序与删除在保存配置或生成预览时持久化。

目录选择器直接浏览本机文件夹，不上传文件。文件列表展示包括未匹配和临时文件在内的扫描结果；临时文件仅展示、不执行整理。目标目录、内部数据和配置的排除目录仍然不扫描。未扫描时显示真实空状态，不使用示例文件假装整理成功。

文件管理左右两栏均可手动输入路径并点击「前往」，也可点击「选择文件夹」逐层选取本机目录；选择左侧或右侧目录只切换对应文件栏，不会自动修改规则整理的来源或目标配置。

侧栏「快速访问」自动列出本机实际存在的桌面、文档、下载、图片、音乐和视频等常用文件夹。点击「选择文件夹固定」可手动添加，也可右键文件夹、右键侧栏最近访问位置，或点击文件栏的星标固定当前目录。自定义固定项可通过侧栏 × 或星标取消；固定列表保存在 FileNest 本地数据中，桌面版和网页版共用。升级前保存在浏览器内的收藏会继续显示在「旧收藏（此浏览器）」中，不会自动删除。

双击文件会交给 Windows 默认应用打开，双击文件夹会进入该目录；文件右键菜单可选择「选择其他应用打开」，由 Windows 显示应用选择窗口。选中一个项目后可点「快捷重命名」或按 F2 输入新名称，文件扩展名保持不变，并在预览确认后执行；选中多个项目时使用原有的批量重命名。左右文件栏可分别按名称、类型、扩展名、大小或修改时间排序，并切换升序、降序；文件夹始终排在文件前面。

目录或扫描结果较多时，页面每次先显示 200 项，可点击列表底部的「继续显示」逐批展开，也可用搜索直接定位；全选仍针对当前筛选的全部项目。网页版与桌面版共用这一布局和行为。

默认不覆盖文件；同名采用跳过或预览时自动编号。移动支持跨盘：先独占复制、校验内容，再移除源项目。复制失败保留源项目；后续失败可能保留两侧或部分结果，记录为“需核对”，不记为成功。首版不跟随符号链接或 Windows 目录联接，排除整理目标与内部数据目录，避免循环整理。

## 规则动作与风险提示

创建规则时可选移动、复制、批量重命名、移入回收站、永久删除，均作用于勾选且匹配的项目。重命名支持前后缀、文字替换、日期和序号；文件保留扩展名，文件夹使用完整名称。重命名和删除无需填写目标目录。

- 文件夹按整体操作，包含内部全部内容；同时选择父目录和子项目时，只执行最外层可执行父目录。未勾选的子文件也属于该文件夹整体，请在确认框核对范围。
- 系统、程序目录、磁盘根目录、系统属性项目和包含内部数据或排除目录的项目会被保护并显示原因；不请求管理员权限、不更改权限。
- 执行前显示具体项目、目标和风险，要求勾选确认；永久删除还必须输入“永久删除”。仅保存规则不会执行文件操作。
- 文件夹操作前计算完整内容快照，执行前复核。目录含临时文件、链接或不可读项目时不整体处理。
- 取消发生在文件夹删除或跨盘移除来源期间时，可能已经部分完成，历史记录显示“需核对”，不承诺原子回滚。
- 回收站仅支持 Windows 本机固定磁盘，通过 [IFileOperation 的回收标志](https://learn.microsoft.com/zh-cn/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperation-setoperationflags)请求回收；失败不会自行改用永久删除。系统回收站不可用时请检查错误记录。

## 从源码启动（开发者）

从 GitHub 下载或克隆项目后，在**自己的电脑**上安装 Python 3.11 或更新版本，进入项目根目录。程序运行仅使用 Python 标准库，不需要安装第三方运行依赖。Windows PowerShell 可先创建自己的虚拟环境（若安装的是 Python 3.12/3.13，相应修改 `py -3.11`；没有 `py` 启动器时，使用自己的 `python.exe -m venv .venv`）：

```powershell
py -3.11 -m venv .venv
$Python = '.\.venv\Scripts\python.exe'
& $Python --version
& $Python main.py
```

已有合适的 Python 环境时，无需重建：将 `$Python` 设为**你自己的**解释器绝对路径，再运行后续命令即可。例如 `$Python = 'C:\路径\到\python.exe'`。不要把个人解释器路径写回项目源码或提交到 Git；`.venv/` 已加入忽略列表。Conda 用户也可先激活自己的环境，然后令 `$Python = (Get-Command python).Source`。Python 环境的创建和依赖安装由使用者自行决定；自动化代理仍须遵守其所在工作区的审批规则。

随后在浏览器打开 http://127.0.0.1:8765 。服务仅监听本机回环地址，不提供局域网访问；在启动窗口按 Ctrl+C 停止服务。不要分别启动两个服务实例；需切换入口时使用页面右上角的按钮。

桌面窗口使用相同的页面和后台服务：

```powershell
& $Python main.py --desktop
```

Windows 上优先在已安装的 Edge 应用模式中打开独立窗口，不需要安装新依赖；找不到 Edge 时改用系统默认浏览器。请点击页面右上角「退出」或在启动窗口按 Ctrl+C 停止服务；仅关闭浏览器窗口不保证停止后台服务。旧 Tk 界面源码仍在 `ui/main_window.py`，但不再作为 `--desktop` 入口。桌面浏览器的独立配置存放在 `.filenest/desktop-browser/`，不会提交到版本库。两个入口都使用 `127.0.0.1:8765`，不能分别启动第二个服务实例。

页面右上角提供「切换到桌面版／切换到网页版」和「退出」。切换只打开另一种窗口，继续使用当前本地服务和同一份配置、预览及历史；原窗口可自行关闭。结束使用时，在任一窗口点击「退出」或在启动终端按 Ctrl+C。请勿同时在两个窗口中编辑同一份预览；任务运行期间不能退出，应等待完成或先取消任务。

## Windows 便携版打包

需要 Windows x64 和自己的 64 位 Python 3.11+ 环境。打包依赖 PyInstaller 6.x；确认要安装到当前环境后，手动运行：

```powershell
& $Python -m pip install 'pyinstaller>=6,<7'
& $Python packaging\build.py
```

构建脚本使用运行它的那个 Python 环境，不再限定开发者电脑上的固定路径；它只检查平台、Python 位数与 PyInstaller 版本，不会自动安装依赖。若由自动化代理执行安装，仍需先按该工作区的规范取得批准。

脚本在项目内 `dist/` 生成带时间戳的 `FileNest-Windows-x64-*.zip`，不覆盖已有版本。打包时包含 `resource/` 图片，并将其中的图标用于 `FileNest.exe`。把整个压缩包交给 Windows x64 用户；用户解压后双击 `FileNest.exe` 进入桌面版，或双击 `FileNest-Web.cmd` 进入网页版，不需要安装 Python。两个入口共用页面和后台，网页入口会自动打开默认浏览器。程序运行期间保留命令行窗口；结束使用时点击页面右上角「退出」或按 Ctrl+C。仅关闭 Edge/浏览器窗口不保证服务停止。不要同时运行两个实例。

分发包的配置和历史保存在当前用户的 `%LOCALAPPDATA%\FileNest`，更新或移动解压目录不会清除它；源码启动继续使用项目内 `.filenest/`。目前未配置代码签名，Windows 可能显示未知发布者，不能保证所有电脑均无拦截；不应关闭安全软件或绕过警告。请从可信渠道分发并附校验值。macOS/Linux 需要分别构建，当前便携包仅面向 Windows x64。

## 结构与数据

- `web/`：网页版与桌面窗口共用的布局和交互。
- `resource/`：项目共用的 Logo 和图片；完整 Logo 为 `filenest-logo.png`，界面与浏览器标签使用 `filenest-icon.png`。后续图片也统一放在这里。
- `web_app.py`：本机 HTTP 服务、后台任务和接口适配。
- `filenest/`：扫描、规则、计划、执行、历史与撤销核心。
- `ui/desktop_window.py`：桌面窗口启动与生命周期；`ui/main_window.py` 保留旧 Tk 界面源码。
- `window_shell.py`：两种窗口的打开方式，供桌面入口与页面切换共用。
- `.filenest/`：两种界面共用的配置和 SQLite 历史记录。

预览计划保存在服务端，只能执行一次；刷新配置或重启服务后需要重新预览。服务校验 Host、请求来源与会话令牌，不允许其他网站直接发起文件修改。

## 验证

```powershell
& $Python -m unittest discover -s tests -v
node --check web/app.js
node --check web/explorer.js
```

`unittest` 是 Python 标准库，无需额外安装；安装了 pytest 的开发者也可运行 `& $Python -m pytest -q`。Node.js 只用于可选的 JavaScript 语法检查，不是程序运行依赖。

测试只在项目内 `test/_tmp` 创建样例文件，覆盖多规则选择、文件夹去重、删除确认、状态变化、取消、跨盘移动与撤销、源删除失败和保护目录。跨盘分支通过模拟跨设备错误测试；回收站的成功路径使用适配器替身，原生接口仅验证不存在项目时安全失败，未对真实资料或真实回收站执行删除测试。
