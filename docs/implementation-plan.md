# FileNest 文件自动处理工具初步方案

## 1. 项目定位与目标

FileNest 面向个人本地文件管理，首版以 Windows 为目标，解决下载目录、桌面和工作资料目录中的分类杂乱、命名不统一等问题，后续扩展自动运行、重复文件检测和内容识别。

核心流程：**选择目录 → 设置规则 → 预览处理结果 → 执行整理 → 查看记录或撤销**。

首版优先保证文件处理可预览、可追踪、可撤销。云同步、多用户、复杂 AI 分类不纳入首版。

## 2. 功能规划

### 2.1 首版核心功能

| 模块 | 功能 | 示例 |
| --- | --- | --- |
| 目录管理 | 添加目录、子目录开关、排除目录 | 扫描下载目录，排除指定文件夹 |
| 文件扫描 | 获取名称、类型、大小、修改时间并统计 | 查看文档、图片、压缩包数量 |
| 规则分类 | 按扩展名、名称关键词、日期、大小匹配 | 名称含“合同”的 PDF 归入合同目录 |
| 文件整理 | 移动或复制，自动建立目标目录 | 图片移入“图片/2026/09” |
| 批量重命名 | 前后缀、文本替换、日期、序号 | `截图_20260915_001.png` |
| 执行预览 | 展示原路径、目标路径、动作和冲突 | 执行前核对移动清单 |
| 冲突处理 | 跳过或自动编号，默认不覆盖 | `报告.pdf` → `报告 (1).pdf` |
| 操作记录 | 逐文件记录结果与失败原因 | 文件占用、权限不足 |
| 撤销整理 | 恢复符合条件的移动和重命名 | 撤销最近一次整理 |

默认分类模板包括文档、图片、视频、音频、压缩包和安装包；支持按年份、月份建立子目录。未匹配文件保持原位置。

### 2.2 增强功能

- 实时目录监控：文件进入目录且完成写入后触发整理。
- 定时整理：按指定时间扫描并执行规则。
- 重复文件检测：先按大小筛选，再以内容哈希确认。
- 重复文件隔离：经用户确认后移入隔离目录，保留原路径记录。
- 规则管理：优先级、启用与停用、导入与导出。
- 执行控制：进度、取消剩余任务、失败重试。
- 通知：完成或失败时提示。

### 2.3 后续可选功能

- 读取文档正文，识别合同、发票、简历等类型。
- OCR 提取扫描件或图片文字，辅助命名和分类。
- 图片格式转换、尺寸调整和压缩。
- PDF 合并、拆分和文本提取。
- 自然语言生成规则，生成后由用户检查再启用。

上述功能作为独立模块按需实施，不作为首版交付条件。

## 3. 规则模型与安全原则

一条规则包含：匹配条件、执行动作、目标路径与命名模板、冲突策略和匹配后行为。

示例：扩展名为 PDF 且名称含“发票” → 移动到“财务/发票/修改年份/修改月份” → 同名自动编号 → 停止匹配后续规则。

首版支持全部条件同时满足；后续可增加任一条件满足和复杂组合。日期规则必须明确使用哪个时间字段，首版可优先使用修改时间。

处理原则：

1. 默认不覆盖、不永久删除用户文件。
2. 排除目标目录，避免循环整理。
3. 每个文件默认仅执行第一条匹配规则。
4. 文件被占用或仍在下载时跳过，自动运行阶段加入稍后重试。
5. 执行前重新检查文件状态，避免预览后发生变化。
6. 撤销前检查文件状态和恢复路径，冲突时提示用户，不强行覆盖。
7. 首版不跟随符号链接或目录联接。
8. 逐文件记录完成与失败结果；中断后不得将未完成操作记为成功。

首版撤销范围为移动和重命名；复制操作的自动撤销另行设计，避免误删用户后续修改的副本。

## 4. 初步技术方案

建议采用 **Python + PySide6 桌面应用 + SQLite**。这是早期选型建议，不代表已安装依赖；当前实现和源码启动方式以 README 为准。开发者可配置自己的 Python 3.11+ 环境，自动化代理安装第三方库前须遵守所在工作区的审批规则。

| 模块 | 职责 |
| --- | --- |
| 桌面界面 | 目录选择、规则编辑、预览、进度和历史 |
| 文件扫描 | 文件信息收集、目录排除和扫描异常处理 |
| 规则模块 | 匹配条件判断和优先级控制 |
| 计划模块 | 生成处理清单、检查路径和冲突 |
| 执行模块 | 移动、复制、重命名及结果记录 |
| 历史与撤销 | 保存操作前后信息并生成恢复操作 |
| 自动任务 | 后续接入目录监控和定时运行 |

将“生成处理计划”和“实际操作文件”分离，手动整理、实时监控与定时任务共用处理逻辑。耗时扫描和文件操作在后台执行，界面显示进度。

## 5. 分阶段实施

### 阶段 1：项目基础与文件扫描

实施内容：

- 建立项目结构、配置和日志模块。
- 搭建主界面，支持添加和移除待整理目录。
- 实现扫描、子目录开关和排除规则。
- 展示文件列表及分类统计。

验收：正确扫描选定目录；单个无权限文件或目录不会导致整个扫描失败；扫描不阻塞界面。

### 阶段 2：规则与执行预览

实施内容：

- 实现类型、关键词、日期、大小条件。
- 提供默认分类模板和规则优先级。
- 生成移动、复制、重命名计划。
- 展示目标路径，标记冲突与无效操作。

验收：每个计划项可解释匹配原因和处理动作；预览不会修改源文件。

### 阶段 3：执行、记录与撤销（首版完成）

实施内容：

- 实现文件处理与同名自动编号。
- 增加进度、失败原因和取消剩余任务功能。
- 保存逐文件操作记录。
- 支持符合条件的移动和重命名撤销。
- 验证占用、权限不足、冲突与执行中断等场景。

验收：完成“扫描 → 预览 → 执行 → 查看记录 → 撤销”；失败不会破坏原始文件；已完成和未完成操作可区分。

### 阶段 4：自动运行

实施内容：

- 增加目录监控和定时整理。
- 检测文件写入状态，防止重复事件重复处理。
- 支持暂停自动处理和失败重试。
- 提供完成和异常通知。

验收：新文件写入完成后能按规则自动处理，留下可查记录；暂停后不触发新操作。

定时任务可先在应用运行期间实现。涉及系统计划任务、开机启动或系统服务时，必须按 `AGENTS.md` 提前说明并征得同意。

### 阶段 5：重复文件与交付完善

实施内容：

- 实现按内容检测重复文件。
- 提供保留建议和用户确认后的隔离处理。
- 完善规则导入导出、设置页及通知。
- 打包 Windows 应用，补充使用说明。

验收：无需开发环境即可运行交付版本；支持日常整理和重复文件隔离；隔离记录可追溯原路径。

## 7. 验证与实施顺序

先完成阶段 1～3，再根据实际使用反馈决定自动运行、查重与内容识别的投入顺序。阶段为功能里程碑，暂不承诺工期。

验证优先覆盖规则匹配、同名冲突、重复执行、执行中断、撤销冲突和路径排除；使用专用样例目录，禁止擅自操作用户真实资料。

编码前需确认当前工作区实际使用的 Python 解释器，不应把个人电脑上的解释器路径写进项目。新增库、环境变更及系统安全相关操作须遵守所在工作区的审批规则。

## 8. 当前实现状态

阶段 1～3 的基础流程已实现，入口为项目根目录的 `main.py`，桌面界面位于 `ui/`：

- 使用 Tkinter 构建桌面界面，不需要新增第三方运行依赖。
- 支持多个来源目录、递归扫描、排除目录、分类统计和逐项扫描错误提示。
- 支持扩展名、关键词、修改日期和大小条件，按规则优先级匹配。
- 支持移动、复制和重命名计划，以及前后缀、文本替换、修改日期、序号和年月目录。
- 预览阶段计算文件指纹并展示目标路径；同名文件可跳过或自动编号。
- 执行前再次校验文件状态，支持取消剩余任务，并将逐文件结果保存到 SQLite。
- 移动和重命名可安全撤销；若文件已变化或原位置出现文件则拒绝覆盖。复制不自动撤销。
- 不跟随符号链接或目录联接，自动排除整理目标和内部数据目录。

原桌面首版仅支持同盘移动；后续网页批量管理扩展见第 10 节。

## 9. 本地网页版

默认入口 `main.py` 为本地网页版，`main.py --desktop` 使用同一套页面与 `web_app.py` 后台，在 Windows 上优先通过已有 Edge 的应用模式显示为独立桌面窗口。旧 Tk 界面源码保留，但不再承担桌面入口。两种入口共用功能和数据，并占用同一个本机端口，因此不能同时启动。使用 Python 标准库 HTTP 服务，无新增第三方运行依赖。

双入口维护约束：桌面版与网页版是用户可选的并列入口，后续所有界面、文案、交互和功能变更均应通过共用页面和后台同步提供，不允许只实现一端（除非用户明确同意例外）。两种页面都提供相互切换按钮；切换在同一个本地服务中打开另一种窗口，不重置配置、预览与历史。桌面入口切到网页版后，关闭桌面窗口不停止服务，仍需在启动终端按 Ctrl+C 退出。

网页包含整理、规则、历史和偏好页面，支持后台扫描和处理、取消任务、服务端一次性预览计划、逐文件结果及安全撤销。仅监听 `127.0.0.1:8765`，不修改防火墙、不提供局域网访问。实际启动服务仍需遵守项目的端口授权要求。


## 10. 网页批量管理扩展

“使用规则”列出全部现有规则并支持多选，使用稳定标识保存选择；新建规则支持图片、视频、压缩包、文档、文件夹等类型筛选，以及移动、复制、重命名、永久删除、回收站动作。

文件夹按整体快照校验，父子重复选择只执行父目录；保护目标、排除项、内部数据和系统路径。跨盘移动采用独占复制、内容校验、移除源项目，失败保留可核对记录；目录处理中断可能产生部分结果。删除需要执行前风险确认，永久删除还要求输入指定文字。应用内撤销限移动和重命名；回收站由 Windows 还原，永久删除不可撤销。
